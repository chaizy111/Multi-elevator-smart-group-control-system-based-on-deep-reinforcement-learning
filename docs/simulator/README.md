# simulator

内核只有配置、领域、交通依赖，无 torch/Web 依赖。相同微秒先完成物理操作，再到达、逐个分配，随后启动本地服务，再逐梯询问空闲重定位。当前决策未提交时状态不推进；旧决策不能重复提交。

开门开始冻结上下客名单，先逐人下客，再逐人上客，最后关门。正在执行的相邻层运动不可反转；重定位被服务任务抢占时保留已走的时间与距离。等待/乘梯/平方超时公平性按事件间区间积分，先积分旧状态，再更新事件，门和启动代理成本在实际开始时增加。

P1 先使用完整 pickup/dropoff 对尾部追加，确保容量安全；P2 增加与 ETA 共享的可行插入。S01 验证 pickup=3s、finish=12s、最终关门14s。

## P2 路线契约

`route_planner.py` 先投影当前冻结操作结束的时间、楼层和载客集合；再枚举 pickup 及其后的 dropoff 槽位，合并相邻同楼层站并前向检查容量和先接后送。最多各保留16槽（尾部必留），成本为接人延迟 + 0.2新增路线时长，平局按槽位序。并非全局最优。ETA 直接使用同一 proposal；提交核对 route_version，未选中的 proposal 无副作用。

## v2边界修复

纯重定位到达后清除连续运动标志，下次从静止出发重新计start；截止时不开始新运动/开门。同微秒导入乘客明确按ID排序。simulator与reward版本均升级，旧模型不再用于新版本评价，历史产物保留于artifacts/legacy/v1。

## v3长程冷却

纯重定位到达后，以到达时刻重新锚定idle review和cooldown，长于30秒的运动也不能立即再次发出重定位决策。抢占转服务不视为纯重定位到达。版本event-v3-arrival-cooldown，旧模型不混用；v2原始产物保留legacy/v2。

## 有界审计

AuditLog将完整JSONL保留在最多2MB的内存spool，超过后只在项目.cache/simulator溢写，最近100条作为快速尾部。归档顺序读取完整记录，临时文件随对象关闭清理；不丢弃审计历史，也不在长运行中保留所有Python事件/快照对象。训练关闭高频审计。该容器只在一致事件边界顺序读写，不对同一Simulator进行并发操作。
