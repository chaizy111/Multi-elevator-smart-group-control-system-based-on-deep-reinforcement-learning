# 基于深度强化学习的多电梯智能群控系统

问题陈述与需求设计｜课程小组项目｜2026年10月24日

## 一、问题陈述

办公楼中的多部电梯需要共同服务不断到达的乘客。一次派梯不仅决定新乘客何时上梯，还会改变已有乘客的接人顺序、送达时间和电梯运行距离。例如，两部电梯接新乘客的时间相同，其中一部接单却可能使原有乘客绕行。因此，只按轮询或最短接人时间选择电梯，难以同时兼顾平均等待、长时间等待与运行代价。

本项目把电梯群控建模为动态序贯决策问题：在乘客到达或电梯空闲时，根据当时可见状态选择服务电梯或空闲梯目标区域，以环境交互反馈训练深度强化学习策略。目标是在统一物理模型、相同客流与完整服务口径下，研究 PPO 相对轮询、ETA、ETA-Zone 的调度表现，并以可视化系统展示输入、决策过程和结果。

## 二、范围、使用者与约束

主要使用者是开展算法实验的学生和检查运行结果的教师。系统面向单机、本地、单用户的教学仿真，支持5—30层、2—8部电梯、每梯6—20人，以及普通办公、早高峰、晚高峰、楼层互访和突发客流。运行可使用真实已训练权重，无需在课堂现场重新训练。

服务对象为到达窗口内的全部乘客；窗口结束后继续运行至服务完成或明确标记截断。策略只能看到已经到达的乘客和公开任务，不能使用未来到达信息。项目不接入真实电梯设备，不研究设备安全认证、紧急制动或多用户生产部署。

## 三、功能需求

| 编号 | 需求 | 可检查的结果 |
|---|---|---|
| F01 | 配置建筑、物理参数、客流及随机种子 | 非法配置被拒绝，合法配置可保存与载入 |
| F02 | 生成或导入乘客流，记录输入身份 | 同一Trace可供各策略重复运行，保存SHA256 |
| F03 | 事件仿真与群控，遵守容量和任务约束 | 乘客无丢失、无重复服务，停站和状态可追溯 |
| F04 | 提供三经典策略与训练好的PPO | 可切换策略，支持同流实验与指标比较 |
| F05 | PPO训练、保存、加载与继续训练 | 使用真实交互与梯度更新，校验权重和语义版本 |
| F06 | 展示仿真、曲线、过程及结果 | 支持暂停、继续、导出乘客表、指标和比较图 |

## 四、数据与深度强化学习设计

输入包括建筑与物理配置、客流配置或乘客CSV，以及可选的已训练模型。每位乘客至少记录编号、到达时刻、起点与终点；运行过程记录分配、上梯、下梯、停站和动作，输出等待时间、乘梯时间、完成率、运行距离及原始归档。配置和Trace分别建立哈希，避免比较不同输入而误判算法优劣。

决策状态由电梯、路线、楼层队列、当前请求和历史客流摘要组成。为降低从路线中隐式推断插单影响的难度，派梯头还接收每台梯的六项公开后果：接人时间、送达时间、新增距离、已有任务接人延误、已有任务送达延误及路线延长。它们仅作为输入，权衡由神经网络学习，不采用固定候选规则代替PPO决策。

派梯动作最多选择8台梯；重定位动作包括原地等待及4个目标区域，两类动作通过合法掩码切换。模型采用共享电梯编码、两层Attention、双任务策略头与价值头。奖励综合等待、乘梯、能耗代理和长等待成本；按事件实际时间间隔计算折扣及GAE，再采用PPO裁剪目标更新。训练、验证、评价客流分离，模型记录训练预算和获选检查点，避免把预算终点等同于最佳模型。

## 五、质量及软硬件需求

| 编号 | 质量要求 | 验证方法 |
|---|---|---|
| Q01 | 正确性：容量合法、服务守恒、终止口径明确 | 单元、属性测试及原始乘客记录独立重算 |
| Q02 | 可复现：输入、配置、模型及版本可定位 | 同流与跨进程回归；权重SHA、配置和日志归档 |
| Q03 | 可解释：展示输入、过程和输出的关联 | 仿真截图、训练曲线、分项指标与同流对比 |
| Q04 | 可维护：仿真、学习、服务和界面解耦 | 分层目录、模块文档、类型/格式/构建检查 |
| Q05 | 可运行：普通CPU环境完成教学演示 | 三种建筑规模的真实API及浏览器端到端测试 |

软件环境为Python 3.11、PyTorch、Gymnasium、FastAPI、React、TypeScript及Node.js，依赖通过锁文件管理。开发使用已配置的conda elevator环境；运行不要求GPU。建议使用至少8GB内存的个人电脑，并为模型、依赖和运行归档保留磁盘空间；这是部署建议，不作为已经测得的最低硬件门槛。

## 六、评价与交付

比较应在同一客流上进行，完整服务后同时报告平均等待、P95等待、乘梯时间、长等待比例和距离；空输入与未完成运行不得以零等待参与排名。效果目标是在受控场景中降低等待，并如实报告距离代价和不同训练种子的差异，不宣称对所有未来客流均最优。交付包括源程序、模型、数据说明、总体设计、关键算法、运行截图、测试证据、演示PPT与小组总结；成员姓名和学号由小组在提交前填写。
