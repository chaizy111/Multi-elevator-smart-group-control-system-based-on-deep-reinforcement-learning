# 演示讲稿与现场顺序

可按8—10分钟的建议节奏演示；实际时长以教师要求为准。

第1页：介绍研究问题。系统不是单台电梯控制，而是多个电梯在同一批动态请求下协作。封面13.14秒是提交801在开发集的成绩，不能直接解释为所有楼宇的保证。

第2页：用手算例子解释为什么只看ETA不够。两台梯接新客都是4.8秒，但一台会延误旧任务。引出让网络直接获得这些后果的动机。

第3—4页：展示四个页面和分层设计。强调所有策略共用物理内核，乘客流可以按Trace复用，前端显示服务端权威状态。

第5页：解释深度RL建模。六项特征只是输入，没有固定调度总分；230维输入进入共享派梯MLP，经合法mask决定动作，新增参数仅768。

第6页：介绍训练闭环。环境采样、事件时间GAE、PPO更新、开发选模；三个微调seed来自同一个预训练PPO，训练预算与获选步数分别记录。

第7—8页：先报告三seed均值的开发改善，再报告单801的等待、P95与距离。不要把两种统计对象混为一谈；固定规则仍是更强的离线参照。

第9页切到真实页面：配置12F4E、早高峰、12人/分钟、120秒、seed9001，选择PPO801，5倍运行后暂停观察，再加速完成，下载乘客CSV与指标。已提供同配置26人完整服务的截图备用；现场结果应由相同输入复现，不以截图代替程序。

随后在实验评价输入9001,9002，执行四策略同流对比，说明这些是已知演示输入。到训练与模型选择801记录，展示真实曲线。

第10页：解释置零消融。性能退化说明模型利用新信息，但分布外消融不能代替独立泛化测试。

第11—12页：给出90/2/5测试与原始重算证据，说明dev冻结和main交付。结尾明确课程开发要求已获认可；严格接近规则门槛尚未全过，确认和最终未打开。

常见问答：

“为什么仍属于深度强化学习？”动作评分由神经网络参数决定，参数通过真实PPO交互更新；后果表不含固定评分系数或教师动作。

“为什么不只用固定规则？”固定规则是很强的参照，本项目研究的是学习方法；材料保留其优势，不把规则成绩算作PPO收益。

“为什么200000步模型却写143360？”前者是完成预算，后者是按开发验证选出的检查点。

“为什么不展示新盲测？”原研究门槛没有通过，冻结协议下未打开确认和最终数据；当前演示和开发成绩如实标注。
