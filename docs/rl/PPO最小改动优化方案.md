# 基于首版流程的 PPO 最小改动优化方案

日期：2026-10-24。此方案对应的实验产物和专用代码已按用户要求删除，仅保留设计文本；当前开展候选后果特征输入PPO研究。

目标：从当前 `ppo-curriculum` 的训练与建模出发，让深度网络通过 PPO 学到更好的调度，争取在完整服务、尾部等待和距离约束下优于 ETA、ETA-Zone、轮询，并接近第二轮的固定候选规则。优先控制修改数量，不恢复已删除的优化轮次。

## 1. 建议采用的最短路线

**先验证训练中的 actor/critic 梯度平衡，优先只调整现有 `value_coefficient`；如果仍有明显差距，再把当前乘客请求提前接入路线编码器。** 前者可以从配置改动开始，后者只增加160个网络参数，不增加候选代价或人为调度分数。

建议只设置两个主要研究因素：

| 因素 | 最小改动 | 希望解决的问题 | 是否改变派梯决策来源 |
|---|---|---|---|
| A：价值项权重 | `value_coefficient` 从0.5对照到0.05；必要时独立验证0.005 | 检查 critic 与 actor 共用编码器、共同裁剪时的优化失衡 | 否，动作仍由 PPO 网络产生 |
| B：请求参与路线编码 | 路线编码输入由8维改为8维路线特征＋5维当前请求 | 网络在压缩路线之前理解“这名乘客与这条路线的关系” | 否，评分完全由学习参数产生 |

扩大验证覆盖和补充诊断日志是两组实验共同的基础工作，也需要开发成本，不能把它们藏在“只改一行”之中。第一轮不同时修改奖励、GAE、重定位规则、网络规模、学习率和训练预算；若A单独达标，就不增加B。

这是一条有代码与数据依据、但仍需实验证明的路线。不能保证两个小改动就能达到固定规则的水平。如果失败，应留下明确结论，再决定是否扩大研究范围。

## 2. 本方案如何保持深度强化学习属性

部署动作始终是：

```text
公开状态 → 深度网络 → 13个动作分数 → 合法动作mask → argmax
```

神经网络的派梯和重定位分数都由 PPO 的环境交互训练得到。本轮不使用固定候选代价、预设优先级、规则分数加神经残差、教师动作标签、行为克隆或规则兜底。

当前观测已经包含公开的接人 ETA，公共路线规划器负责物理可行插入；这些属于现有环境接口。继续向网络提供 ETA，并不等于让 ETA 规则代替网络选梯。禁止新增的是第二轮那套“枚举候选代价并按固定系数直接评分”的决策路径。合法动作mask同样属于可行性约束。

固定候选规则只作为离线评价参照，三种经典算法也只用于评价与约束核验；它们的动作或逐动作代价不进入训练标签、策略分数或奖励塑形。算法定义仍属于带双任务 actor-critic 的 PPO，而不是启发式调度器。

## 4. 证据与假设必须分开

### 4.1 历史效果说明存在改进空间，但不能冒充当前默认模型的新评价

原正式标准矩阵为45场景×20条客流，PPO列是独立初始化101/202/303三个模型的平均，**不是默认 `ppo-curriculum`**。

| 策略 | 平均等待/秒 | P95/秒 | 距离/层 |
|---|---:|---:|---:|
| ETA | 34.43 | 121.36 | 139.96 |
| ETA-Zone | 25.19 | 98.26 | 168.00 |
| 轮询 | 24.64 | 78.11 | 218.71 |
| 首版三个独立PPO平均 | 29.32 | 89.16 | 217.17 |

数据见[正式数据解读](../../reports/formal/策略效果解读.md)。等待改善与距离增加同时存在，因此“只把平均等待变小”不足以完成原目标。

第二轮保留的固定规则在其独立历史标准矩阵中平均等待为10.9677秒，401残差PPO为11.0727秒，见[保留对照](../../references/round2/reports/comparison.md)。它使用另一组客流，不能与上表直接计算提升幅度，也不能把10.9677秒当作新测试的固定达标线。未来须在同一组新输入上重新评价各参照；规则不一定是最优策略，只是较强的性能参照。

### 4.2 当前课程日志出现明显的优化尺度变化

以下是本次只读重算现有 `updates.csv` 得到的各update记录中位数，没有重新训练。

| 指标 | T2 | T3 |
|---|---:|---:|
| 原始 value loss | 0.0526 | 20.6489 |
| 裁剪前总梯度范数 | 0.4507 | 65.9073 |
| explained variance | 0.6948 | 0.4551 |
| 平均 KL | 0.001277 | 0.000523 |

来源：[T2日志](../../artifacts/training/t2/updates.csv)、[T3日志](../../artifacts/training/t3/updates.csv)。日志中的 `gradient_norm` 是每个update内各minibatch裁剪前范数的平均；T3共118条update记录，其平均范数全部超过当前裁剪上限0.5。这不等于每一个minibatch都被裁剪。

已确认的实现事实：优势被标准化，价值目标仍使用原回报尺度；`policy_loss + 0.5 × value_loss - 0.01 × entropy` 共同反向传播，所有参数一起按0.5裁剪。T3开始域随机化后，价值误差与梯度尺度显著增大。

**待验证假设**：价值学习可能占据共享编码器的大部分梯度，使策略学习效率下降。现有日志没有分别保存共享参数上的actor/critic梯度，不能据此认定原因已经查明。特别是Adam对梯度整体缩放有一定抵消作用，不能把 `0.5/65.91` 直接解释成实际参数更新只剩0.76%。

T3验证等待从40960步的13.8893秒变为60000步的17.9990秒，说明继续训练没有在这3个验证流上单调改善；它不是新测试结果。日志中各损失数值也不能直接当作各模块的梯度贡献。

### 4.3 请求信息进入路线网络的时机值得小范围修改

当前流程先对每层路线特征编码并做mean/max池化，随后才在派梯头拼接请求编码：

```text
路线 → 与当前请求无关的路线摘要 → 电梯编码 → Attention → 拼接请求 → 派梯分数
```

源码里路线含楼层、待站标志、接送人数、首次到站时间与顺序。mean/max作用于有效楼层，包括没有停靠的楼层。**不能断言路线顺序完全丢失**，因为顺序本身是输入；但请求无关的64维压缩可能难以保留“本请求起终点附近哪些停靠最重要”。

第二轮规则的一个优势是显式评估派给各梯的后果。本轮不复制该计算，而是研究能否让小型深度编码器更容易学到当前请求与已有路线的关系。是否足以缩小性能差距，必须通过B单独与组合消融判断。

### 4.4 已有无Attention消融是备用证据

原300条同流消融中，无Attention等待19.6093秒，完整seed101为30.5144秒，约低35.74%；无Attention距离仍达221.22层。见[原消融](../../reports/formal/ablation_summary.csv)。

这只支持“简化模型值得复查”，不能证明Attention普遍有害，也没有解决距离约束。为控制变量，A/B主实验继续保留Attention；`attention=false` 可作为后续单独的低成本架构候选，不与两项主改动同时堆叠。

## 5. 改动A：先用现有配置检验价值项平衡

### 5.1 先诊断，再确定是否值得修改

在训练客流的短试运行中，按固定间隔，对同一个minibatch分别计算：

1. actor损失与加权critic损失在共享编码器上的梯度范数及夹角；不执行额外优化步骤。
2. 联合梯度裁剪发生比例、裁剪系数分布、dispatch/reposition分支实际参数变化量。
3. 原始value loss、explained variance、回报分布、两个任务的KL/熵，以及合法动作数。
4. 分模式/负载的完整服务、平均等待、P95、距离，而非只看训练reward。

熵梯度单独记录或明确归入actor项；诊断使用 `autograd.grad` 等方式，不覆盖正式梯度、推进优化器、改变采样RNG或更新额外统计状态。派梯/重定位分组只是日志切分，GAE仍沿原始完整事件时间链计算。

若critic梯度并不持续占主导、或小权重只让critic失去拟合能力，就不把该猜测强行作为优化结论。全局裁剪频繁本身不是bug。

### 5.2 首选仅改一个已有超参数

保持原四目标奖励，比较：

```text
对照：value_coefficient = 0.5
A首选：value_coefficient = 0.05
条件备选：value_coefficient = 0.005
```

0.05是一个预先指定的十倍缩小试验值，不是已经测出的最优值。0.005仅在诊断仍显示价值梯度主导时进入额外开发试验；不得在最终测试结果出来后更换。参数先在独立开发验证上冻结，再进入正式A/B矩阵。

`value_coefficient` 调整“学会估值”相对“学会选动作”的优化权重，不是减少等待、能耗或公平性在环境奖励中的权重。策略仍使用PPO目标，critic仍预测原单位回报，GAE与奖励版本不需要因此变更。

A的验收重点不是KL越大越好，而是：策略参数确有更新，价值估计没有持续崩溃，独立验证的服务和约束改善。同一批训练样本上训练loss下降不能代替这些证据。

### 5.3 固定系数不足时的有条件替代方案

仅当固定系数难以跨负载保持合理梯度比例时，才考虑“按回报尺度归一化价值误差”，替代固定小系数方案：

```text
m2 ← 0.95 × m2 + 0.05 × mean(stop_gradient(return)^2)
scale2 = max(1, m2)
value_loss = mean((V - stop_gradient(return))^2) / scale2
```

首个rollout用实际二阶矩初始化，整个rollout的多轮PPO更新使用同一冻结尺度；尺度仅来自训练数据，写入checkpoint并在resume时恢复。V、GAE、bootstrap仍保持原单位，同时保留未缩放value loss日志。它是价值损失的预条件化候选，不是完整PopArt，也不保证共享梯度冲突消失。

这一替代方案需要修改trainer，可能过度减弱高回报场景的价值学习；只有固定系数试验不足时再开新实验，不与A首选叠加，也不算作当前最小方案的必做项。

## 6. 改动B：请求先进入路线编码，再做池化

### 6.1 网络定义

当前路线编码器是 `MLP(8, 32, 32)`。修改为：

```text
每梯每层输入 = concat(该层8维公开路线特征, 当前请求5维特征)
条件路线特征 = MLP(13, 32, 32)(每梯每层输入)
路线摘要 = concat(masked_mean(条件路线特征), masked_max(条件路线特征))
```

请求原有5维是起点、终点、方向、已等待时长、有效标志。将同一请求广播到每台电梯的每个有效楼层，其他输入和mask语义沿用当前实现。没有派梯请求时使用原有全零请求；不用额外编写重定位偏好。

摘要仍是64维，后续88维电梯编码、Attention、224维派梯头、重定位头和critic尺寸均保持原定义。唯一新增参数是首层的 `5 × 32 = 160` 个权重；开启Attention时参数量由426631变为426791。策略没有人工代价公式或固定系数，路线与请求之间哪些关系有用由PPO训练决定。

修改后：

```text
路线＋请求 → 条件路线摘要 → 电梯编码 → Attention
                                        ↓
                         当前上下文 → 双任务策略和critic
```

该设计保留每梯共享参数与电梯置换等变性，继续适配不同楼层/电梯数量。它只是把已有信息提前使用，不能恢复观测中本来就没有的逐乘客完整目的地关系，也不等于精确预测每个动作的代价。

### 6.2 初始化与版本兼容

为了区分结构收益与初始化变化，可从同一T2检查点初始化B：原首层8列权重逐项复制，新增请求5列初始化为0，其他参数完全复制。迁移时输出应与旧网络在浮点容差内一致；训练后新增列通过PPO获得梯度。不可要求不同矩阵计算实现逐位相同。

这是显式新架构初始化，需要单独的架构版本、配置开关、模型ID与受检迁移入口。原 `load_model()` 只构造旧 `ActorCritic(attention=...)` 且严格校验版本，因此不能仅改 `network.py` 就认为训练/注册/页面加载已经兼容。旧模型走旧构造路径，新增输入列只在显式迁移时补零；错误尺寸应明确拒绝。

不能用 `strict=False` 静默漏加载，也不能把新结构的权重保存到原 `ppo-curriculum` ID下。

## 7. 共同的选模与评价基础

### 7.1 修正验证覆盖过窄的问题

当前 `validate_policy()` 只取最多3个基础场景，每场景1个固定seed，而且按综合成本选best。不能通过把更多场景塞进 `scenarios` 就声称扩大了验证：当前代码仍会截取前3项，还会同时改变训练采样候选。

后续应增加独立 `validation_scenarios`，首选3建筑×5交通×3负载×3条输入＝135次验证/模型检查点；训练域与课程继续按原设置。统一常规验证的到达窗口、排空上限、初始状态，所有策略共用相同输入。每20次update验证一次，各候选的验证次数一致。

验证记录完整率、平均等待、P95、总距离、原四项成本和按场景结果。没有乘客的cohort标记无效；有未完成乘客的cohort不得以已接到乘客均值排名。

选模分两层：先要求完整服务，再用P95与距离约束筛选，最后按等场景权重平均等待选择。约束暂时都不通过时保留预先定义的约束违反程度与Pareto结果，标为“无可行模型”；可以用于诊断或下一阶段初始化，但不能作为达标模型。

新选模规则对所有A/B组相同。原冻结模型单列评价，不能因研究流程改变而覆盖它。若仅重新选模就改善，应明确把改善归因于选模，而不是A/B。

### 7.2 对照与数据隔离

每次正式评价至少包含：冻结 `ppo-curriculum`、新流程PPO对照、候选PPO、ETA、ETA-Zone、轮询、第二轮固定候选规则。第二轮401残差PPO可作为附表，不参与当前候选选优。

固定规则通过归档中的明确版本和六系数运行，保持float32与Stay语义。实现隔离的离线评价入口；复核两版本模拟器/路线/指标语义及输入哈希一致，不让归档源码意外进入当前生产训练路径。规则分数与动作不作为PPO的训练输入。

旧9001–9020、第二轮93001起的客流及本线程已观察数据只能用于历史诊断。未来开发验证、一次确认与最终测试须使用新的互不重叠清单，并在运行前对所有保留训练/实验manifest查重；不能仅凭数字较大断言未使用。当前训练实际seed范围为100000–999999，可在其外预留开发、确认、最终三个独立范围，具体清单实施时冻结。

12F3E、18F5E继续排除于训练和选模，24F7E、30F8E用于外推评价。它们的历史效果已经公开，宜称为“训练未见建筑”，不能声称研究人员从未见过这类场景。新输入的最终测试只能在配置与模型冻结后打开。

## 8. 以少量实验逐步决定是否增加改动

### 8.1 D0：诊断与基础准备

先完成共同验证、分量梯度和模型身份核验。短试运行只使用训练/开发数据，不注册生产模型。若critic失衡假设没有支持，跳过A，直接对B进行有无对照。

### 8.2 D1：最小配置改动

使用A首选0.05与0.5对照，保持原网络。0.005作为预先规定的条件备选，只有开发诊断支持时追加，记录搜索次数与成本。若A达到所有效果要求，停止结构扩展。

### 8.3 D2：必要时执行两个因素的消融

冻结A设置后，对至少3个训练seed，例如701/702/703，执行以下矩阵。编号只作建议，启动前核对未与既有实验命名冲突。

| 组别 | 价值项设置 | 请求条件路线编码 | 用途 |
|---|---|---|---|
| P0 | 原0.5 | 关闭 | 新共同验证下的训练对照 |
| PA | A已冻结设置 | 关闭 | 测A独立收益 |
| PB | 原0.5 | 开启 | 测B独立收益 |
| PAB | A已冻结设置 | 开启 | 测交互与组合收益 |

每个seed独立运行原T0→T1→T2，再从该seed的同一T2检查点分叉四个T3组；B按上述方式显式迁移。T0–T2继续原课程与选模，T3各组采用相同的新验证规则。seed仅配对随机性，策略不同会导致事件轨迹和环境重置时刻不同，不能声称训练样本逐条相同。

先保持每组T3六万决策。完整矩阵的名义预算为每seed七万前缀＋四组各六万，共31万；3seed合计93万决策，另计D0/D1成本与向量采样尾部取整。复用已经完成且配置/初始化/验证完全相同的D1组，不重复训练；每组均记录其继承前缀，不能把共同前缀算成零训练。

以开发验证决定保留哪一组，不在最终测试挑家族或seed。若只有PAB有效，应报告交互效应；不能把联合收益分别算给A和B。只有单独有效且满足约束的更简单组优先保留。

### 8.4 D3：扩大预算与独立确认

开发结果有一致改善但尚未达到性能目标时，才把已选方案及P0对照的T3预算同时提升到20万；后续80万为另一个有条件阶段，不默认全部执行。学习率、clip、熵系数等其余设置沿用基线，避免无法归因。

当前 `resume` 拒绝预算等配置改变。需要从相同T2前缀另开20万配置，或在实验开始就冻结总预算并设置中间观察点；不能把六万训练后的重置优化器续训当作同一条20万轨迹。

最终候选至少补齐5个独立课程seed，全部使用同一配置、同一选模规则。按预先冻结的确认集，例如45场景×10流，执行一次确认；确认未通过就不打开最终测试。新增seed较弱时同样保留，不用“最好seed”替代总体。

最终标准矩阵建议45场景×30条新流；另行冻结1800秒长窗口、训练未见建筑/外推和压力场景。所有对照同流、同初始状态、同物理参数、同cohort口径。压力未完成时同时报告未接到人数、未完成人数、完成率及等待下界，禁止按条件均值宣称胜出。

## 9. 把“优于”和“接近”定义成可检验目标

以下阈值是建议在实施前冻结的研究标准，**不是已经达成的结果，也不改变原方案要求**。单位是每条完整运行先算指标、再按场景和训练seed等权汇总；P95为每流P95的汇总，不混成全体乘客的一个P95。

令 `W` 为平均等待，`T` 为P95，`D` 为总距离，`R` 为固定候选规则，`b` 分别为三种经典算法。

| 要求 | 建议判据 |
|---|---|
| 可靠服务 | 标准、长窗口和常规泛化中全部cohort完成；不删除失败运行 |
| 平均等待优于三基线 | 对每个b，跨seed总体 `W_PPO / W_b ≤ 0.95`；每个训练seed的总体均值也均低于三基线 |
| 尾部和距离约束 | 对每个b，要求每个训练seed的总体 `T_PPO / T_b ≤ 1.05`、`D_PPO / D_b ≤ 1.05`；原中负载相对ETA的5%/5%/5%标准仍单列核验 |
| 接近固定规则 | 同流 `W_PPO / W_R ≤ 1.10`；进一步≤1.05记为更严格目标，不把10%说成已经相当 |
| 分组稳定性 | 按5模式×3负载、各建筑分别报告；建议每个模式负载组对三基线的等待恶化均不超过5%，避免总体均值掩盖明显退化 |
| 统计不确定性 | 以模型seed、配对Trace分层重采样，不以乘客当独立样本；给出均值比和配对差的区间 |

“稳定”针对预先冻结的分布、分组和训练重复，不意味着每条Trace都严格更好。只有3个训练seed的先导不能直接作稳定结论，5个seed仍要披露估计精度限制。

对于三项“优于经典”与一项“接近规则”的四个主要等待结论，可预注册Bonferroni处理：每项使用单侧98.75%置信上界。三基线的等待比上界须低于1；规则比上界须不超过1.10。点估计5%改善与区间排除无改善是两条不同要求；若区间过宽，就报告证据不足。P95/距离等其他指标分别披露区间，不能把描述性容差冒称同时统计显著。

若等待显著改善但距离超限，应写“等待改善、综合目标未达成”；若仅优于ETA，应写“优于ETA”，不能写“优于三种传统方法”。新规则等待若仍接近历史10.9677秒，10%带宽约是12.0644秒；这只是解释阈值的算例，正式判定只能用新同流规则结果。

## 11. 暂不加入的方向与失败后的决策

| 方向 | 本轮处理及理由 |
|---|---|
| 候选代价、规则残差、规则兜底 | 不采用，避免把收益再次建立在预设调度逻辑上 |
| 模仿ETA或候选规则 | 不采用本轮；即使可作为RL预训练，也会引入教师收益归因问题 |
| 先改四项奖励或奖励塑形 | 暂缓；当前日志显示能耗贡献并非始终很小，不能只根据0.05系数判断其无效 |
| 同时分离actor/critic网络和优化器 | 暂缓；改动大于调整现有系数，且共享参数冲突需先诊断 |
| GNN、LSTM、更大Attention或多智能体 | 暂缓；暂无证据表明增加容量优先于优化和请求条件编码 |
| 默认关闭重定位、推理改随机采样 | 暂缓；会改变任务/部署策略，须单独命名和评价 |
| 只拉长预算 | 有开发改善趋势才执行；当前验证并非越训练越好 |
| 无Attention | 若A/B未带来稳定增益，可独立复验现有开关；保持同预算、多个seed和约束，不据单seed宣称胜出 |

补充判断：T3日志按原奖励公式加权后，等待/乘梯/能耗/公平性累计贡献约为39.60%/12.14%/21.12%/27.14%；T2能耗约58.20%。这是已采样轨迹上的成本占比，不是梯度占比或最优权重依据。盲目把能耗权重乘数倍，可能使原本较难的等待目标更差。

如果A/B都失败，先判断：价值估计是否仍不稳定、策略是否实际更新、错误是否集中在路线表示缺失或长时信用分配、是否只是距离约束不通过。根据证据再选择一个新因素研究；不把所有备选同时装进下一轮，也不反复查看最终测试来决定改动。

## 12. 方法依据与适用边界

PPO保留环境采样与多轮代理目标优化的基本方式，本方案没有更换算法家族。[PPO原论文](https://arxiv.org/abs/1707.06347)

实现与优化细节会显著影响策略梯度效果，因此优先诊断训练而非立即增加结构复杂度有研究依据；但本文A的具体系数、B的请求条件编码是针对仓库提出的假设，并非这些论文已经验证过的电梯结论。[Implementation Matters](https://arxiv.org/abs/2005.12729)、[What Matters in On-Policy RL](https://arxiv.org/abs/2006.05990)

多训练seed、配对输入和区间报告用于减少从少量运行中得出过强结论的风险；论文支持评估原则，不提供本项目的达标保证。[Deep Reinforcement Learning at the Edge of the Statistical Precipice](https://arxiv.org/abs/2108.13264)

实施时的优先顺序是：**核验与共同验证 → A配置试验 → 必要时B及四组消融 → 有趋势才扩大预算 → 五seed确认 → 一次冻结测试**。最终只保留被独立结果支持的最小改动组合。
