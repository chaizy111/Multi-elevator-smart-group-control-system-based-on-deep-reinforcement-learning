# 零基础前端使用手册

本手册对应main课程提交版，PPO默认模型为ppo-consequences-s801-n200000。您可以把它理解为“已经学习过的一位调度员”；页面比较的是同一座楼、同一批乘客交给不同调度员的结果。

## 打开系统

在项目文件夹的终端依次执行README中的启动命令，或在已配置环境里运行make demo。浏览器打开http://127.0.0.1:8000。启动后终端窗口应保持打开；关闭该窗口会停止后台服务。首次安装按根目录README操作，系统已附带模型，无需先训练。

## 先完成一场演示

点击左侧“01 场景配置”。楼层填12、电梯填4、容量填12，到达窗口填120秒、随机种子填9001；选择早高峰，到达率填12人/分钟。到达窗口表示允许新乘客出现的时间，不是仿真必须停止的时刻。

“调度算法”选择PPO，在“已训练模型”选择ppo-consequences-s801-n200000。运行速度选择5倍后点击“启动仿真 →”。原始ppo-curriculum是旧参照，请根据模型名称区分。

进入“02 实时仿真”后，楼层旁数字显示排队人数，轿厢数字显示当前载客量与容量。点击“暂停”可观察状态，“继续”恢复；运行速度选择最快可以迅速完成。底部可查看乘客和最近决策。运行完成后，请确认“已完成”和完成率，再查看最终指标。

点击metrics.json或passengers.csv的下载链接，可保存指标和每位乘客的记录。等待时间是乘客到达至上梯的时间；乘梯时间是上梯至下梯时间。P95表示大约95%的乘客等待不超过该值。运行距离越少通常意味着较少行程，但它不是实测电量。

“停止”表示提前结束，可能仍有人未服务；“重置”创建相同配置与输入的新运行，不是继续旧结果。比较最终效果时不要把未完成运行与完整服务运行混在一起。

## 比较四种调度算法

先在配置页设好建筑和客流，点击“03 实验评价”。实验模型选801，独立测试种子输入9001,9002，点击“运行同流对比”，等状态变为COMPLETED。界面只接受9001—99999的逗号分隔整数；这里的“独立测试”是页面用途标签，已使用过的演示种子不能再次当成研究盲测。

系统会把每个种子对应的同一批乘客交给轮询、ETA、ETA-Zone和所选PPO，形成8次运行。先看最终cohort表的等待、P95、距离与完成率，再看等待—距离图和乘客等待分布。散点越靠左表示等待越短、越靠下表示距离越少，图例对应不同策略。

少量页面实验用于演示和探索，不代表135组研究统计。不同种子、建筑和模式可能得到不同排名；需要比较研究效果时，查看课程报告和冻结研究表，而不是只挑一次最好结果。

## 看训练与模型

点击“04 训练与模型”，训练记录选consequences-s801-n200000。页面显示真实Reward、验证成本和等待曲线，可查看模型SHA与获选步数。200000是本轮训练完成的预算，143360是开发验证选出的检查点；二者不是矛盾。

页面负责展示日志，实际训练通过终端显式启动，预算较长，不需要为了演示点击或运行训练命令。802/803是同一原始已训练PPO上的其他微调种子，不是三个从零独立训练的模型。

## 常见问题

页面连接失败时，先查看后台服务终端是否仍在运行，地址和端口是否与启动命令一致。端口被占用可改用8001，并在浏览器打开相应地址。

找不到模型时，在项目根重新运行python -m elevator_control.submission；安装器会检查SHA，遇到已改动文件时明确拒绝覆盖。不要把任意权重文件改名冒充该模型。

最快模式下动画很短是正常现象，可改用1倍或5倍；最终曲线来自真实归档。空客流没有可定义的平均等待，页面不把它当作零秒获胜。未完成或截断结果不应参与最终排名。

首次提交前补上课程、小组、姓名和学号；个人总结草稿应按实际贡献核实。截图和数据见[课程材料](../coursework/课程项目报告.md)，需求文档与PPT见[交付目录](../../submission/README.md)。
